# lightaskd の設計意図

初期設計で何を優先し、なぜ現在の構成を選んだかを残す文書です。操作方法は [README](README.md)、AI 向けの手順は [Skill](skills/lightaskd/SKILL.md) を参照してください。

## 解決したい課題

個人の依頼や後で対応したいことを、AI に小さなローカル台帳へ登録・検索してもらいたい。Slack のリンクを渡し、期限とともに残すような利用を想定しています。

Jira などへ登録する運用では、認証やサービスの重さ、他人への可視性が個人用途の負担になります。Jira は権限がプロジェクト単位のため、自分だけに見える非公開タスクを作ること自体が手軽にできず、専用プロジェクトや権限設定の依頼が必要になります。一方、自由形式の Markdown を AI に更新させるだけでは、説明や重複したメモが増え、必要なタスクを見つけにくくなります。

そこで、手元のフォルダで保持でき、呼び出したときだけ短時間で動く、構造化されたタスク台帳を用意します。Markdown 自体を否定するものではありません。用途に制約のない文章を台帳へ蓄積し続けることを避けたい、という判断です。

## 保存する情報を小さく保つ

タスクの中心は `title`、`query`、`due_at`、`source_uri` です。期限のないタスクもあるため、現在の実装では期限は任意です。`query` は後で何をするかが分かる短い説明であり、登録時に実行する命令や SQL ではありません。

出どころは元の URL などで保持します。Slack 本文を読めない場合に、その内容を推測して埋めません。背景、判断理由、知識の関係などの詳細は、既存の GraphRAG の記録ルールに従って扱います。台帳には汎用の `notes` や自由形式の `metadata` を設けません。

状態、リビジョン、再送識別子、作業権の期限、更新日時は、運用と同時操作のための情報です。これらを追加することは、台帳を第二の知識保管庫にすることとは区別します。

## GraphRAG と記録先を奪い合わない

併用対象は [graphrag-knowledge](https://github.com/suzuki0keiichi/claude-plugins-suzuki0keiichi/tree/main/plugins/graphrag-knowledge) です。lightaskd を導入した結果、以前ならグラフへ残っていた判断や背景が「タスクに保存したから十分」と扱われて消えることを、設計上のリスクと考えています。

- GraphRAG は lightaskd に依存しません。lightaskd を使わない・削除した場合にも、グラフ側の運用を成立させます。
- リンクは lightaskd からグラフへの一方向です。参照文字列はタスク側だけに保持し、逆リンクや通知を要求しません。
- lightaskd はグラフを検索・検証・更新しません。ユーザーや独立した処理が既に知っている参照を受け取ります。
- lightaskd への保存は、GraphRAG の既存の記録ルールを変更・代替・抑止しません。同じ会話から独立に両方へ記録することはあり得ます。
- lightaskd の利用だけを理由に GraphRAG を新たに起動することもありません。

これは AI に守らせる利用契約でもあります。タスク CLI だけで、別の AI ワークフローがグラフへ記録したかどうかを保証することはできません。

## 手動呼び出しと使い方の発見を両立する

「この Slack リンクを期限付きで保存して」という文章だけでも自動起動させない、という選択です。ユーザーが保存先を選び、AI が会話の内容から勝手に lightaskd を選択しないようにします。検索も同じ境界で扱います。

一方、指定しても場所や使い方が分からない状態は避ける必要があります。そのため、CLI の所在・入力形式・保存先の選択・エラー処理を持つ Skill を同梱し、手動呼び出し専用にします。

- Codex: `$lightaskd`。`agents/openai.yaml` の `allow_implicit_invocation: false` で暗黙起動を無効にします。
- Claude Code: `/lightaskd:lightaskd` (plugin 名で名前空間付き)。`SKILL.md` の `disable-model-invocation: true` でモデルによる起動を無効にします。

通常文中の名前だけでは、製品によっては明示呼び出しとして扱われません。確実な入口は明示セレクターです。Skill を登録しておけば、ユーザーが毎回 CLI の配置場所や JSON 形式を説明する必要はありません。

保存先が見つからない場合も、AI が別の場所へ新規台帳を作る理由にはしません。既存の保存先を確認し、初期化は場所を指定した明示的な依頼で行います。

この制御は Skill の選択に対するものです。CLI を直接実行できる主体への OS レベルの書き込み禁止ではありません。また、タスクを登録しても作業の実行、定期監視、通知は始まりません。

## Node と SQLite を選んだ理由

短い CLI と Node 標準の `node:sqlite` を組み合わせ、外部ランタイムパッケージへの依存をゼロにしています。DB サーバー、常駐プロセス、MCP サーバーは現在の構成に不要です。Node.js 22.13 以上を実行環境に要求することが、この小ささとの交換条件です。

配布・依存管理には pnpm だけを使います。npm レジストリ形式のパッケージを作ることと、npm コマンドを使うことは別です。通常のインストール経路では pnpm の利用を設定と `preinstall` で確認します。CLI の実行自体は Node で直接行い、操作のたびに pnpm を起動する時間を加えません。

初期プロトタイプの参考計測では、Windows 上の Node 24 で、新規 Node プロセスの起動から 1 万件中 20 件の一覧取得まで平均約 51 ms でした。これはプロセスを再利用しない計測ですが、OS のファイルキャッシュを排除していません。pnpm や AI ツール呼び出しの時間を含む値でもなく、完全コールド状態や全環境の性能を保証する値ではありません。

この用途では起動を含む短い待ち時間を優先し、常駐による高速化を必要条件にしません。

## 同時操作はローカル DB の仕組みで支える

同じ PC の複数の AI セッションや CLI プロセスから、同じローカル台帳へ要求が届くことを想定します。

- SQLite のトランザクションと WAL を使います。書き込みは DB が直列化します。
- ロック待機は接続初期化の先頭で設定し、初期化中の競合にも待機を適用します。待機時間は有限で、すべての要求の成功を無期限に保証するものではありません。
- `request_id` により、同一登録の再送でタスクが増えることを防ぎます。再送は同じ識別子と同じ内容で行います。
- `revision` と `--if-revision` により、更新元が読んだ後の変更を検出します。この保護を使うには呼び出し側がリビジョンを指定します。
- `claim` の期限付き作業権は作業の調整に使います。外部作業の一度限りの実行を保証したり、作業そのものを開始したりはしません。

`synchronous=FULL` は最大スループットより保存の耐久性を優先する選択です。高頻度の分散ジョブキューとしては設計していません。

## フォルダ単位の可搬性とプライバシー

台帳は `taskbox.json` と `taskbox.db` を持つフォルダです。互換性のため、CLI 名に `lightaskd` を加えてもこれらの名前と既存の `taskbox` コマンドを維持しています。

移動先に対応する Node があれば利用できる構成を目指します。ランタイムを内蔵した単体実行ファイルではなく、すべての OS の組み合わせで動作確認済みという意味でもありません。Skill 登録のシンボリックリンクや外部設定のパスは、移動後に更新が必要な場合があります。

利用中は WAL/SHM ファイルも存在し得ます。フォルダ移動は利用を止めて行い、稼働中のバックアップには `snapshot` で整合したコピーを作ります。クラウド同期やネットワーク共有上の同じ DB を、複数 PC から同時更新する使い方は対象外です。

グラフ参照にマシン固有の絶対パスを使えば、フォルダだけを移してもリンク先は移りません。安定したグラフ ID や vault 内の相対的な参照を渡すことで、この依存を小さくできます。参照の意味は呼び出し側が管理します。

ローカル保存によりタスク管理サービスの認証や共有範囲設定を不要にしますが、DB の暗号化は実装していません。ファイルを読める主体には内容が見えます。Slack など参照元へのアクセスには、そのサービスの認証が別途必要です。タスク DB は Git 管理から除外します。

## 今後変更するときの判断基準

新しい機能が、暗黙の保存先選択、自由文の無制限な蓄積、GraphRAG への依存・逆リンク、必須の常駐プロセスを導入するなら、この設計意図の変更として扱います。便利そうだからという理由だけで既存の境界を広げません。

パッケージ名 `explicit-taskbox`、ライセンス `UNLICENSED` はプロトタイプ段階の設定です。公開配布の条件、完了タスクの保存期間・削除方針、ランタイム同梱は未確定であり、自動削除や同期機構があると解釈しないでください。
